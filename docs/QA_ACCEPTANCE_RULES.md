# 场景图最终验收规则

本规则用于验收所有当前 `READY_FOR_QA` 商品，以及后续新生成的场景图。目标不是判断“场景好不好看”，而是先确认场景里的艺术作品有没有被改坏。

## 1. 验收对象

每个商品至少需要以下三类证据：

1. 原作品高清图或可确认完整作品内容的原始参考图。
2. 最终场景图 1。
3. 最终场景图 2。

缺任何一类证据，不允许判定通过。

## 2. 每张场景图必须检查的项目

### A. 完整性

- 矩形作品四边是否完整。
- 圆形作品完整圆周是否完整。
- 是否有作品内部区域被画框、卡纸、家具、植物、灯具或其他物体遮挡。
- 是否因为裁切、生成错误或构图导致原作边缘/角落消失。

### B. 内容一致性

逐项对照原作：

- 主体数量是否一致。
- 主要色块、线条、纹理、文字、人物、动物、花朵、建筑等是否丢失。
- 是否凭空新增原作不存在的元素。
- 是否发生镜像、旋转、局部重绘、内容替换。
- 是否把抽象细节“补全”成别的内容。

场景光线造成的亮暗、色温变化可以存在，但不能导致作品本体结构变化。

### C. 装裱一致性

- 原有画框是否完整保留。
- 原有卡纸/留白是否完整保留。
- 外框颜色、厚度、比例是否明显被改错。
- 原本无固定画框的作品，是否被误加了与原作冲突的固定画框。
- 原本有框的作品，是否被错误展示成裸画芯。

### D. 比例与透视

- 场景中作品是否出现明显横向拉伸、纵向压缩、弯曲、翘曲。
- 正常斜视透视允许存在，但应先对作品区域做透视校正，再与原图比较。
- 透视校正后的作品轮廓和原作长宽关系应一致，不得肉眼可见变形。

### E. 尺寸感

结合 Manifest 的真实尺寸判断：

- 小尺寸作品不能被展示成占满整面墙的大画。
- 大尺寸作品不能被缩成桌面小装饰。
- 多幅场景之间的尺度不能互相矛盾。

尺寸感只能用于判断明显错误，不要求从单张室内图反推出毫米级物理尺寸。

## 3. QA 证据图

对所有待验收商品生成可回看的对照证据，建议目录：

`previews/qa_comparisons/`

每个商品至少一张对照板，文件名：

`Pxxx_作品名_QA.jpg`

对照板必须至少包含：

- 原作品参考图。
- 场景图 1。
- 场景图 1 中作品区域的透视校正/正视裁片。
- 场景图 2。
- 场景图 2 中作品区域的透视校正/正视裁片。
- 商品序号、作品名、真实尺寸、原装裱信息。
- 每张场景的判定和失败原因。

不要只上传缩得看不清作品细节的大拼版。全量拼版可用于总览，但单商品 QA 必须保留足够分辨率。

## 4. 状态定义

最终状态只允许使用：

- `QA_PASS`
- `QA_FAIL_CROP`
- `QA_FAIL_CONTENT`
- `QA_FAIL_FRAME`
- `QA_FAIL_SCALE`
- `QA_FAIL_PERSPECTIVE`
- `QA_NEEDS_MANUAL`

同一商品只要任意一张最终场景失败，就不能把整个商品标记为 `QA_PASS`。

## 5. Manifest 需要补充的字段

建议在现有 CSV 后追加：

- `artwork_lookup_key`
- `original_reference`
- `scene_1_qa_status`
- `scene_1_qa_reason`
- `scene_2_qa_status`
- `scene_2_qa_reason`
- `product_qa_status`
- `qa_evidence_path`

其中 `artwork_lookup_key` 建议使用 `艺术家-作品名`。不要把 token、cookie、API key 写进 CSV。

## 6. 统计口径

最终报告必须使用互斥状态统计，并保证合计严格等于商品总数：

`QA_PASS + 各类 QA_FAIL + QA_NEEDS_MANUAL + PENDING_GENERATION = 商品总数`

“官网场景”“原商品场景”“混合来源”属于来源维度，不能再与成功数量直接相加，否则容易产生重复统计。
